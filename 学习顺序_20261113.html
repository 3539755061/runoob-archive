学习顺序 · 按「AI 不可替代性」排序

依据同一目录里的 150 个教程评级与章节量重排：先学 AI 替不了你判断的部分，后学 AI 写得比你好、你也看不出对错的部分。
假设：零基础或转行、每周 8–10 小时、目标是能独立交付一个能跑的小项目。不要求全部学——按阶段取舍，后置项按需查。

0 三条排序原则

这次不按「技术栈」排，也不按「从易到难」排，而是按你在这件事上还有没有判断权排。

原则一：先学「能验证 AI 输出」的东西

AI 已经能写出能跑的代码。真正稀缺的是：它写错了你能不能看出来。能不能看出 SQL 少了个 JOIN 条件、HTTP 少了个状态码分支、指针越界、复杂度是 O(n²)——这些判断来自语言语义、运行模型和调试经验，AI 只能帮你写，替不了你判断。

原则二：框架与配置项放最后

框架细节是 AI 最擅长的部分，也是变化最快的部分：你现在背熟的 Bootstrap 类名、ECharts 配置项、Spring 注解，半年后可能连版本都换了，而 AI 随时能给最新写法。先把「语言 + 数据 + 系统」打牢，框架用到再学。

原则三：越靠后，手写越少、调试越多

阶段 0–1 你手写为主；到阶段 3–4，合理的工作方式是「AI 生成 + 你审查 + 你调试」。学习重心也随之从「记住语法」移到「读代码、写测试、定位问题」。

一句话：AI 让「写」变便宜，让「判断」变贵。这份顺序就是把时间投在「判断」上。

1 AI 替代度分级（决定先后）

每一类内容给一个「AI 替代度」：高＝AI 基本能独立完成、你只需验收；中＝AI 能写但你需要判断与修改；低＝AI 帮不上多少，必须自己建立。

内容AI 替代度为什么在顺序里的位置
样板代码、CRUD、表单校验、接口胶水高模式固定、可复制，AI 生成质量已超过多数初学者的手写后置，用时生成
CSS 布局微调、UI 组件库类名高试错成本低，改到对为止即可后置，只留最小必要
正则表达式、图表配置、构建脚本高查文档比记规则快，AI 可直接给可用版本后置，遇到再查
文档排版、注释、提交信息高格式化与表达类工作随时用
SQL 基础查询、数据清洗脚本中AI 会写，但表结构理解、结果对不对、性能如何要你判断中段，重判断
API 设计、数据建模、测试设计中方案类工作，AI 给选项，取舍在你中段
性能优化、线上排障中依赖对系统的真实理解与观测数据后段
调试与排错、读陌生代码低需要在你自己的环境里复现、观察、假设、验证最前
数据结构与复杂度、语言语义低决定你能不能看出「能跑但很糟」最前
操作系统 / 网络 / 进程模型低环境问题的根因都在这层前段
版本控制与协作流程低涉及团队状态与历史，AI 只给命令最前
需求拆解、边界判断、验收标准低决定「做什么」比「怎么写」更贵贯穿

「高」不等于不学：你需要看懂它、能验收它；只是不必在前期花时间背。

3 阶段 0 · 工作台（1–2 周）

用哪几篇：Git（16 节）、Markdown（18 节）

目标：能自己建环境、留痕、回滚。这一阶段学的不是命令，是「可复现」。

  • Git：提交、分支、合并、回滚、看 diff、看懂冲突标记。不要一上来背 rebase 的全部参数。
  • Markdown：写清楚一件事（标题层级、列表、代码块、表格）——这直接决定你给 AI 的提示质量。
  • 编辑器：VS Code（25 节）当查阅，不必专门学；会搜索、会开终端、会设断点就够。

验收：新建仓库 → 写一份 md → 提交 → 故意改坏 → 用 diff 找出来 → 回滚到上一个好版本。全程不看教程。

这一阶段 AI 替代度低：Git 的历史与分支状态是「你所在环境的真实状态」，AI 只给命令，执行与判断仍是你。

4 阶段 1 · 编程基本功（6–8 周）

用哪几篇：Python3（81 节）、数据结构与算法（44 节）；替代路线 C（63 节）、C 语言数据结构（20 节）

目标：建立「程序怎么跑」和「代码好不好」两个判断力。这是全表里最不该交给 AI 的一段。

  • 语言只选一门，不要同时开两门。Python3 上手快、能直接接阶段 2 的数据与脚本；想更懂内存与指针就选 C。
  • 数据结构与算法：数组、链表、栈队列、哈希、树、排序、查找、复杂度。重点是能手写并说清为什么，不是刷题量。
  • 加练：调试。故意写错、看报错、加断点、二分定位。这项能力贯穿后面所有阶段。

验收：
① 不看资料手写 10 个基础算法；
② 给一段 200 行的陌生代码，说清它做什么、改一个行为；
③ 拿到一个报错，5 分钟内定位到行。

反常识：这一段最「低效」——手写、报错、重来。但正是这些低效动作在建立判断力。让 AI 代写这一段的练习，等于把地基外包。

5 阶段 2 · 数据与系统（5–6 周）

用哪几篇：SQL（67 节）、MySQL（41 节）、HTTP（10 节）、网络协议（29 节）、Linux（29 节）

目标：知道数据存在哪、请求怎么走、程序跑在什么上。这三件事是「AI 给的方案靠不靠谱」的主要判断依据。

  • SQL 先于具体数据库：联表、聚合、子查询、索引为什么会失效。MySQL 只学安装、建表、字符集、慢查询看哪里。
  • HTTP 不求全：方法、状态码、头、缓存、连接复用。能看懂一次真实请求的报文就达标。
  • 网络协议只读「协议栈概览」，别陷进 TCP 三次握手细节；本归档的 TCP/IP 教程只有 5 节，别拿它当主线（见第 8 节）。
  • Linux：文件、权限、进程、管道、日志、端口排查。够用即止。

验收：设计 3 张表并写出联表查询 → 用 curl 看一次请求与响应 → 在 Linux 上让一个脚本常驻并把日志写进文件。

这一阶段 AI 替代度中：SQL 它写得很快，但「这条查询会不会扫全表」「这个状态码该怎么处理」仍要你判断。

6 阶段 3 · 交付能力（4 周）

用哪几篇：Docker（22 节）、Playwright（45 节）、正则表达式（14 节）

目标：把「本地能跑」变成「别人也能跑」。这是业余与可交付之间的分界线。

  • Docker：镜像、容器、Dockerfile、Compose、卷。目标是把阶段 2 的项目一条命令跑起来。
  • 测试：Playwright 写 5 条端到端用例。重点不是语法，是「选哪几条测」——这就是测试设计。
  • 正则：够用即止，会让 AI 生成、你负责验收；学它是为了能看懂并改。

验收：别人拿到你的仓库，按 README 三条命令跑起来；改坏一处，测试能报红。

7 阶段 4 · 三个方向分叉（8–10 周）

到这一步再选方向，不要一开始就选。三个方向的共同前提都是阶段 0–3。

A · 后端

FastAPI（38）或 Flask（53）→ RESTful（10）→ Swagger（13）；Java 路线用 Java（56） + Servlet（24） 过渡

重点在「接口契约」：资源怎么分、状态码怎么给、错误怎么返回、鉴权放哪。框架本身让 AI 写，你负责设计与验收。

B · 前端

HTML（76）→ CSS（只取盒模型/定位/Flex，约 30 节）→ JavaScript（89）→ TypeScript（72）→ Vue3（58）或 React（41）

真正值钱的是 JavaScript 与 TypeScript：事件循环、闭包、原型、类型收窄。CSS 与组件库属于「AI 替代度高」，够用就行。

C · 数据 / AI

NumPy（26）→ Pandas（54）→ 机器学习（58）→ PyTorch（39）→ LangChain（43）

顺序不能反：没有 NumPy/Pandas 的数组与表操作，直接上 PyTorch 只会变成调参。机器学习先学评估与过拟合，再学模型。

选一个，别三个都要。三个方向共用前 16 周，分叉后各自 8–10 周；同时推进会变成三个都半途。

9 压缩版与常见坑

如果只有 12 周（每周 8–10 小时）

砍掉分叉与交付，只保留「能判断 + 能跑通」：

  1. 第 1 周：Git + Markdown（34 节）
  2. 第 2–7 周：Python3（81 节）＋ 数据结构（44 节，只做数组/哈希/树/排序）
  3. 第 8–10 周：SQL（67 节）＋ HTTP（10 节）＋ Linux（29 节，只学文件/权限/进程/日志）
  4. 第 11–12 周：用 FastAPI（38 节）做一个带数据库的小接口，Docker 打包，写 3 条测试

12 周做不到「精通」，但能做到：看得懂 AI 写的后端代码、能判断 SQL 与接口对不对、能把它跑起来。这已经超过「只会让 AI 生成」的人。

四个常见坑

  1. 先学框架：框架里 80% 是配置与约定，AI 最擅长；先学它等于把最容易被替代的部分放在最前面。
  2. 刷完再动手：每阶段的验收都是「做出来」，不是「看完」。章节数是上限，不是任务。
  3. 同时开两条线：语言、方向都只选一个；同时学 Python 和 Java，通常两个都停在语法层。
  4. 把教程当权威：本归档的教程示例普遍停在 2012–2015 年（Python3 首章打印 3.3.2、Vue 页自述 2.1.8）。语法可用，接口与版本以官方文档为准。
