说明：怎么分组、怎么评分

抓取时间：2026-11-13 21:13（北京时间）｜ 抓取范围：runoob.com 首页「全部教程」列出的 12 个板块、150 个教程入口 ｜ 抓取方式：本机 curl / Python 直连，逐个教程首页取回 HTML 后解析

一、为什么要重新分组

runoob 首页把教程按技术栈分成 12 个板块（Python / 数据科学、AI / 智能开发、前端开发、后端开发、数据库、移动开发、DevOps / 工程化、编程语言、计算机基础、XML / Web Service、.NET、网站建设）。这个分法适合「找某个技术」，但不适合「决定先学什么」：同一板块里既有十年前的老技术，也有上个月刚上的新工具；「编程语言」与「后端开发」之间也没有区分「语言」和「用语言做服务」。

所以本归档做了一次按用途的重排：保留官方 12 个板块的全部 150 条，一个不漏，把它们归入 9 个阅读分组。归并规则只有一条——按「你拿它来干什么」分组，而不是按它挂在哪个菜单下。例如 Electron 官方挂在后端，但它是桌面应用框架，归入「移动与桌面」；「编程语言」与「后端开发」合成一组，因为它们的共同用途是「写服务端程序的语言与组件」。

二、评级口径

每一条教程给两个判断，互不替代：

字段取值含义
适用性推荐技术在役、讲解成体系、可以直接作为该主题的第一入口
可用内容可用，但存在偏浅、偏旧、依赖官方文档补齐等问题
谨慎技术进入维护期／已停更，或内容明显过薄、名实不符；只在特定场景用
弃用技术已淘汰或页面已无实质内容，不建议投入时间
时效在役 / 维护期 / 已停更 / 历史技术本身在 2026 年的使用状态，与页面新旧无关

评级依据不是「页面看起来顺眼」，而是可复现的三类证据：

  1. 可达与规模：150 条全部 HTTP 200；章节数取自每个教程首屏左侧目录的链接数；「在线运行」＝页面内含「尝试一下」运行入口；「测验」＝页面含测验入口。
  2. 页面自述：教程简介里写明的版本与年代（例如 Vue 页写明「基于 Vue 2.1.8」「Vue 2.0 于 2023-12-31 停止更新」，Android 页写明「2015 年 7 月开始撰写」，Swift 页写明「基于 Xcode 8.2.1 / Swift 3.0.2」）。
  3. 技术现状：该技术在 2026 年是否仍是主流、是否已被官方停止维护（如 Python 2 于 2020-01-01、Vue 2 于 2023-12-31、AngularJS 于 2021-12 结束支持）。这一类属于行业共识，不依赖 runoob 页面。

一个必须先说清的立场：runoob 是第三方教学站，不是官方文档。它的价值在「中文、成体系、能快速跑通第一个例子」，不在「版本最新、覆盖最全」。本归档的评级只回答「值不值得作为入口」，不回答「内容是否逐字正确」——正式使用时，接口、版本、配置项仍应以官方文档为准。
